# 宠物表情包订单系统

本体系将客户填写、运营管理和 Skill 生产分开，避免把所有照片与成品塞进一个文档。

## 四个组成部分

1. `客户需求表模板.md`：复制到问卷、表单或私聊中给客户填写。
2. `outputs/01a01f1b-ccef-7783-b034-e17a696b4bd5/订单总表.xlsx`：人工运营主视图，每个订单一行，只保存路径，不嵌入原图。
3. `orders/<订单编号>/`：每笔订单的独立文件夹，隔离照片和成品。
4. `order.json`：机器可读订单文件，供 `$pet-sticker-studio` 使用。

## 标准操作

1. 客户付款后，发送客户需求表。
2. 使用 `scripts/new-order.ps1` 创建订单目录和 `order.json`。
3. 把客户照片放入该订单的 `input/`。
4. 打开 `outputs/01a01f1b-ccef-7783-b034-e17a696b4bd5/订单总表.xlsx`，新增一行并粘贴订单目录与照片目录路径。
5. 使用 `$pet-sticker-studio` 检查照片并生成身份卡。
6. 每完成一个节点，更新总表中的“当前状态”和订单内的 `status-log.md`。
7. 交付完成后记录原图删除日期，到期后按隐私规则处理。

## 创建订单示例

在项目根目录运行：

    powershell -ExecutionPolicy Bypass -File .\order-system\scripts\new-order.ps1 -PetName "团子" -PetType cat

可指定订单编号：

    powershell -ExecutionPolicy Bypass -File .\order-system\scripts\new-order.ps1 -OrderId "PS-20260820-001" -PetName "团子" -PetType cat

脚本不会覆盖已有订单。如果目录已存在，会停止并提示更换编号。

## 调用 Skill

    使用 $pet-sticker-studio 处理这个订单。订单文件在 D:\workspace\pet_meme\orders\PS-YYYYMMDD-NNN\order.json，宠物照片在对应 input 文件夹，输出到该订单目录。先检查照片并生成身份卡；资料不足时给出补图清单。如果 auto_approve_sample=false，请在身份卡阶段等待我确认。

## 数据原则

- 订单编号不使用客户真实姓名。
- 订单总表不嵌入原始照片或成品，只保存受控路径。
- 案例展示授权默认关闭，且与订单处理授权分开。
- 不在公开目录保存联系方式、原始照片或未授权成品。
- 删除照片前核对订单状态、售后状态和约定保存期限。
