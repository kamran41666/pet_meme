# 宠物表情包自动化工作流与表单实施方案

更新日期：2026-08-20  
适用商品：19.9 元 / 10 张宠物表情包体验包

## 一、最终建议

首版采用：**小红书成交 + 飞书多维表格表单收集资料 + 本地 PetMemeStudio.exe 建档与启动 Codex**。

首版不需要自己部署服务器。商家在电脑上打开程序、点击“读取最新表单”，程序临时向飞书接口取回记录和照片，然后在本地建立标准订单。只有以后需要“客户提交后立即自动推送”“电脑关机时也能收单”“无人值守 24 小时运行”时，才需要一台公网服务器或云函数。

小红书开放平台当前公开的商家接口重点是商品、订单、库存和包裹等电商数据，并没有适合本项目的通用消费者定制需求表单接口。因此，小红书负责流量、成交和订单号，定制照片与授权由外部表单承接。参考：[小红书开放平台 API 文档](https://school.xiaohongshu.com/en/open/index.html)。

## 二、完整业务流程

1. 在小红书发布无硬广感的宠物样品笔记。
2. 用户通过商品页下单 19.9 元体验包。
3. 商品详情、下单自动回复或人工私信发送飞书表单链接。
4. 用户填写小红书订单号、宠物信息、制作要求、授权，并上传 5–8 张照片。
5. 商家打开 `PetMemeStudio.exe`，粘贴飞书完整链接，点击“检查连接与字段”后读取未处理表单。
6. 程序取得表单记录，自动映射为内部标准字段；商家检查或修正。
7. 程序下载照片，建立 `orders/PS-YYYYMMDD-NNN/` 订单目录。
8. 程序生成 `order.json`、`intake.json`、`status.json`，同时刷新 `outputs/订单总表-程序同步.csv`，并把“已同步”和本地订单编号回写飞书。
9. 点击“检查能否开工”：检查授权、图片数量、文件格式和大小；照片角度、清晰度仍由人工确认。
10. 点击“开始两张试作”：程序调用本机 Codex，读取项目内 `pet-sticker-studio` Skill，先生成身份卡与“开心、委屈”两张无字试作。
11. 正式客户订单暂停，商家人工确认宠物身份与试作；若不合格，记录补图或返工原因。
12. 确认后点击“继续完整生产”，生成剩余八张、排中文、质检、预览和交付包。
13. 通过小红书约定渠道交付；只有客户明确同意案例展示时，才能将成品用于后续笔记。

## 三、飞书表单应该是什么样

在飞书多维表格中新建“表单视图”，字段名称请尽量使用下表原文，程序会自动识别。带“内部”的字段不放给客户填写。

| 顺序 | 字段名 | 飞书字段类型 | 必填 | 说明 |
|---|---|---|---|---|
| 1 | 小红书订单号 | 单行文本 | 是 | 用于与已付款订单对账 |
| 2 | 小红书昵称 | 单行文本 | 是 | 避免仅依赖手机号 |
| 3 | 联系方式 | 单行文本 | 否 | 用于交付或补图联系，不公开 |
| 4 | 宠物名字 | 单行文本 | 是 | 成品称呼 |
| 5 | 宠物类型 | 单选：猫 / 狗 | 是 | 首发只处理猫或狗 |
| 6 | 是否只有一只宠物 | 单选：是 / 否 | 是 | 选择“否”时人工拒绝或转套餐外 |
| 7 | 参考照片 | 附件 | 是 | 5–8 张；建议只收 JPG/PNG/WebP |
| 8 | 必须保留的可见特征 | 多行文本 | 否 | 例如眼睛、花纹、尾尖、耳朵 |
| 9 | 不希望出现的元素 | 多行文本 | 否 | 例如衣服、帽子、项圈 |
| 10 | 是否保留照片中的项圈 | 单选：是 / 否 / 无项圈 | 是 | 选择“否”会映射为禁止项圈 |
| 11 | 其他备注 | 多行文本 | 否 | 只接收体验包范围内需求 |
| 12 | 照片权利确认 | 单选：是 / 否 | 是 | 必须为“是”才能建生产订单 |
| 13 | 案例展示授权 | 单选：不同意 / 同意 | 是 | 默认不同意，必须与制作授权分开 |
| 14 | 表单状态 | 单选 | 内部 | 新提交 / 已同步 / 待补图 / 生产中 / 已交付 |
| 15 | 本地订单编号 | 单行文本 | 内部 | 例如 PS-20260820-001 |

表单开头建议写明：照片只用于本次订单制作；案例展示需要另行选择；体验包只处理单只猫或狗、固定风格十张；错字、多肢体、关键花纹丢失属于客观质量问题，主观换风格不属于无限修改。

## 四、使用什么服务

| 方案 | 首版建议 | 费用与门槛 | 是否需要服务器 | 适用阶段 |
|---|---|---|---|---|
| 飞书多维表格表单 | 推荐 | 可先用现有飞书能力验证；需创建企业自建应用和配置权限 | 手动同步不需要 | 现在到日均约 10–20 单 |
| 金数据 | 暂不推荐 | 官方说明 API 与 Webhook 依套餐开放，低成本验证不占优 | 轮询 API 不需要；Webhook 需要 | 已经购买相应套餐时 |
| 自建网页表单 | 暂不推荐 | 要承担域名、存储、安全、备份和隐私合规 | 需要 | 稳定规模化以后 |
| 纯手工私信收图 | 仅兜底 | 免费但容易漏字段、错授权、难追踪 | 不需要 | 极少量内测 |

飞书多维表格支持表单、自动化和开放 API，适合把客户提交转成结构化记录。参考：[飞书开放平台云文档常见问题](https://open.feishu.cn/document/server-docs/docs/faq)。金数据官方说明 API 和 Webhook 按付费版本开放，Webhook 需要可公网访问的接收地址。参考：[金数据开放平台说明](https://help.jinshuju.net/next/articles/openjinshuju)。

## 五、程序调用哪些接口

程序当前直接调用飞书官方 HTTP API，不依赖 Codex 内置连接器：

1. `POST /open-apis/auth/v3/tenant_access_token/internal`：使用 App ID 与 App Secret 获取临时访问令牌。
2. `GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records`：分页读取表单记录。
3. `GET /open-apis/drive/v1/medias/{file_token}/download`：下载附件照片。

程序不会把 App Secret 写入订单文件或运行日志。当前版本也不会永久保存飞书凭据，程序重启后需要重新填写；这是为了避免测试阶段把密钥明文落盘。

飞书后台需要完成：

1. 创建企业自建应用。
2. 开通读取多维表格记录、读取/下载云文档附件所需权限。
3. 发布应用版本。
4. 在目标多维表格右上角将该应用添加为“文档应用”，授予访问权。
5. 从链接中取得 App Token，从数据表设置中取得 Table ID。

飞书记录会先标准化为以下中间结构：

  "source_record_id": "recxxxxxxxx",
  "xhs_order_id": "小红书订单号",
  "customer_nickname": "客户昵称",
  "contact": "联系方式",
  "pet_name": "团子",
  "pet_type": "cat",
  "must_keep_features": ["左眼上方浅色斑", "深色尾尖"],
  "must_not_include": ["帽子", "项圈"],
  "photo_rights_confirmation": true,
  "case_display_authorization": false,
  "attachments": [
    {"name": "photo.jpg", "file_token": "boxxxxxxxxx"}

```json

  "must_not_include": ["帽子", "项圈"],

  "output_directory": "orders/PS-20260820-001",
  "auto_approve_sample": false,
  "style_profile_id": "launch-warm-rounded-v1"

```

## 七、是否需要 OpenAI API

当前程序默认调用电脑上已安装并登录的 Codex 命令，因此内测阶段不要求单独填写 OpenAI API Key。程序把图片和订单留在本地项目内，由 Codex 按 Skill 推进。

如果以后希望脱离 Codex 桌面环境、在服务器上无人值守批量运行，则需改为 OpenAI API 模式，并单独配置 API Key 与用量预算。OpenAI 的 Responses API 可接收文本和图片输入并输出文本或 JSON；图像生成/编辑可使用 GPT Image 模型的图像接口。参考：[Responses API](https://developers.openai.com/api/reference/resources/responses) 与 [GPT Image 2](https://developers.openai.com/api/docs/models/gpt-image-2)。

## 八、程序功能与边界

当前 `PetMemeStudio.exe` 已具备：

- 中文本地界面，自动打开默认浏览器；服务只绑定 `127.0.0.1`，不是公网网站。
- 手工录入客户需求并多选本地图片。
- 导入 JSON 或 CSV 的第一条记录。
- 读取飞书多维表格记录并自动映射中文字段。
- 自动解析飞书普通 `/base/` 链接中的 App Token 与 Table ID。
- 检查飞书字段完整性，只展示未处理记录，并在建档后回写状态。
- 通过飞书记录编号阻止重复建立订单。
- 下载飞书附件并重命名为稳定照片编号。
- 建立标准订单目录和三份 JSON 文件。
- 自动刷新 `outputs/订单总表-程序同步.csv` 与 `outputs/order-index.json`。
- 检查授权、5–8 张图片、扩展名和大小。
- 明确拦截 HEIC/HEIF 后续生产，要求先转换。
- 启动 Codex 两张试作或完整生产，保留运行日志。
- 打开订单文件夹，查看当前状态。

当前不做的事情：

- 不自动发布小红书笔记，不自动私信客户；这涉及平台规则和账号风险。
- 不绕过身份卡、两张试作和最终视觉质检的人工判断。
- 不把飞书 App Secret 永久保存到电脑。
- 不覆盖原有 `订单总表.xlsx`；程序另建可直接用 Excel 打开的同步 CSV，避免损坏已有工作簿。
- 不把客户照片上传到自建云端。

## 九、第一次启用清单

1. 双击 `desktop-app/dist/PetMemeStudio.exe`。
2. 先用“新建订单”手工建立一笔自己的样品单，选择 5–8 张 JPG/PNG/WebP。
3. 勾选照片权利确认；自有样品才勾选自动通过身份卡。
4. 在生产队列点击“检查能否开工”。
5. 点击“开始两张试作”，观察 Codex 日志和订单目录产物。
6. 样品流程跑通后再创建飞书表单及自建应用。
7. 飞书同步成功后，用一笔内部测试提交验证字段名、附件下载和授权映射。
8. 最后再把表单链接放到小红书商品详情或售后回复中。

## 十、何时升级为服务器模式

满足任一条件再考虑服务器：日均订单超过手工同步能力；必须在客户提交后数分钟内自动响应；需要多人同时处理；需要电脑关机后仍自动收单；需要统一密钥管理和审计。

升级后结构为：飞书 Webhook → 云函数/API → 对象存储与订单数据库 → 生产队列 → OpenAI API → 审核后台。升级前不要为了“看起来自动化”承担服务器成本和隐私风险。
